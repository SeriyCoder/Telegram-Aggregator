## Problem

У проекта пока нет исполняемого приложения, повторяемого Python-инструментария и проверяемой схемы локального хранения. Без этой основы нельзя безопасно начинать сбор, аутентификацию и работу с личными данными; решения о путях, секретах, лимитах и границах веб-доступа должны быть приняты до появления соответствующего кода.

## Scope

**In scope**

- Создать Python-пакет с `src`-структурой, повторяемой установкой и документированными командами запуска, тестов, проверки типов, линтинга и форматирования.
- Добавить валидируемую локальную конфигурацию. База и будущие файлы сессии располагаются в каталоге пользовательских данных вне репозитория; секреты передаются через переменные окружения, а отслеживаемый пример содержит только пустые или демонстрационные значения.
- Создать начальную версионируемую SQLite-схему и проверяемую инициализацию/миграцию базы. В основу входят источники и публикации с внешними идентификаторами; уникальность публикации в источнике предотвращает дубли на уровне хранения.
- Запускать только локальную команду без HTTP-сервера и не реализовывать аутентификацию в MVP-01. До появления веб-маршрута с личным содержимым аутентификация обязательна.
- Зафиксировать пределы обработки: не более 500 публикаций за один запуск сбора; размер страницы по умолчанию 50, верхний предел — 100. MVP-01 добавляет настройки и их валидацию; сбор и интерфейс, использующие пределы, появятся в следующих пунктах.
- Подготовить офлайн-тестирование конфигурации, миграций и локального запуска без сетевого сервера; обновить инструкции запуска и точные команды инструментария.

**Out of scope** (at least two)

- Подключение Telethon, создание/использование Telegram-сессии, сбор публикаций, обработка ожиданий API и повторы — MVP-02.
- Правила фильтрации, теги, закладки, FTS5 и пользовательские сценарии работы с контентом — MVP-03.
- Веб-сервер и аутентификация в MVP-01; защищённый веб-доступ, адаптивная лента и эксплуатационные процедуры резервирования/восстановления — MVP-04.
- Медиа, облачные сервисы, публичное размещение и туннели.

## Approach

Следовать ограничениям разделов «Архитектурные ограничения» и «Этапы и критерии приемки» спецификации. Инструментарий и модули должны соответствовать слоям из Python-инструкций: конфигурация в `config`, SQLite в `adapters/storage`; будущий веб-слой не получает Telegram-клиент или сессию. Для миграций использовать версионирование SQLite без отдельного миграционного сервиса. Проверки работают на временных локальных файлах и не открывают сетевых соединений.

Утверждённый набор инструментов: Python 3.12 или новее, pytest, Ruff для линтинга и форматирования, mypy для проверки типов. Для путей пользовательских данных использовать платформенный каталог вне репозитория; секреты не хранить в репозитории и не записывать в логи.

Пользователь подтвердил вариант без аутентификации и HTTP-доступа в MVP-01: команда запуска инициализирует локальную базу и завершается. Это позволяет отложить аутентификацию без нарушения правила: каждый будущий маршрут, способный выдавать личное содержимое, должен требовать аутентификацию. LAN-доступ и безопасный транспорт остаются за MVP-04.

**Rejected alternative:** хранить базу, сессии или реальные секреты в каталоге проекта ради простоты запуска — каталог проекта может попасть в контроль версий или синхронизируемое хранилище, поэтому данные следует помещать в пользовательский локальный каталог.

## Privacy and Credential Safety

| Question | Answer |
| --- | --- |
| Is any Telegram credential or session material introduced, moved or exposed? | Нет. MVP-01 не подключает Telegram и не создаёт сессию; он подготавливает правила для будущего локального хранения сессионного файла вне репозитория. |
| Can an unauthenticated client reach any content-bearing route or file? | MVP-01 не открывает HTTP-сервер или маршруты. Каждый будущий маршрут с личным содержимым должен требовать аутентификацию; локальные файлы не раздаются как статические ресурсы. |
| Does the change alter where local data or session files are stored? | Да. Выбран каталог пользовательских данных вне репозитория; база создаётся там, сессия Telegram появится только в MVP-02. |
| Could an error, log, template or response reveal secrets or private content? | Не должно. Секреты не включаются в ошибки и логи; тесты проверяют редактирование/отсутствие значений в захваченных сообщениях и ответах. |
| Does the change affect rate-limit handling or remote connectivity? | Нет. В MVP-01 нет Telegram-адаптера и внешних сетевых запросов; соблюдение ожиданий API и соответствующие тесты входят в MVP-02. |
| How it is proven by tests | Тестами проверить отсутствие сетевого сервера и вызовов, отсутствие секретов в ошибках и логах, валидацию локальных путей и лимитов и создание/миграцию SQLite. Отказ неавторизованным запросам проверяется до появления маршрутов с личным содержимым. |

## Подтверждённые решения

1. Python 3.12+, pytest, Ruff и mypy; точные команды включить в Python-инструкции.
2. База находится в пользовательском каталоге вне репозитория, будущие секреты передаются через окружение; `.env.example` не содержит реальных значений.
3. Лимит сбора — не более 500 публикаций за запуск; страница по умолчанию содержит 50 записей, верхний предел — 100. Значения проверяются конфигурацией.
4. Проверку Telegram rate limit выполнять в MVP-02, когда появится соответствующее поведение; в MVP-01 проверять отсутствие внешних сетевых вызовов.
5. MVP-01 запускается только локально, без HTTP-сервера и аутентификации; аутентификация обязательна до появления веб-маршрутов с личным содержимым.

Противоречие в [тестовой инструкции](../../../.github/instructions/tests.instructions.md) устранено отдельным изменением контура, записанным как CONTOUR-02. Проверка ожидания Telegram и отсутствия обходных повторов остаётся обязательной для соответствующего кода в MVP-02.
