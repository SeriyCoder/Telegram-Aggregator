## Problem

Пользователь хочет локально хранить текст публикаций выбранных Telegram-каналов за выбранный период, без дубликатов и без риска для своего аккаунта. Прямое чтение каналов собственной программой через Telegram API требует, по [условиям Telegram API, п. 3.3](https://core.telegram.org/api/terms), поддерживать официальные спонсированные сообщения каналов. Поэтому реальный доступ в текущей сборке заблокирован. Нужен способ получить публикации уже сейчас, не нарушая условия Telegram и не передавая программе вход в аккаунт.

## History

Первая утверждённая версия этой записки предусматривала подключение через Telethon и разработку только с тестовыми данными до выяснения условий Telegram. Эта основа реализована: миграция `0002_sync.sql`, курсоры, лимит запуска, сохранённый cooldown, блокировка аккаунта и защищённое хранение сессии. Все реальные Telegram-операции завершаются явным отказом. 2026-11-12 пользователь выбрал **импорт официального экспорта** и **только каналы**. Готовая API-основа остаётся без изменений и по-прежнему заблокирована. Прямой доступ требует отдельного будущего пункта.

## Scope

**In scope**

- Новая локальная команда импорта одного файла `result.json`, созданного официальным Telegram Desktop через меню канала **⋮ → «Экспорт истории чата»** в формате JSON.
- Принимаются только экспорты одного канала: `type` равен `public_channel` или `private_channel`. Группы, личные чаты, боты и полный экспорт аккаунта отклоняются с понятным объяснением.
- Источник создаётся или обновляется по заголовку экспорта: числовой `id` канала и `name`. Отключённый источник не импортируется.
- Сохраняются только сообщения `type = "message"` с непустым текстом или подписью. Служебные сообщения и записи только с медиа без текста пропускаются и учитываются в отчёте.
- Текст собирается из частей `text_entities` в исходном порядке; при их отсутствии используется поле `text`. Время публикации берётся из `date_unixtime` и записывается в UTC в существующем формате `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ`.
- Идемпотентность: повторный или перекрывающийся импорт не создаёт дублей и не заменяет уже сохранённую версию. Используется существующий ключ «источник + номер сообщения».
- Атомарность: один файл импортируется одной транзакцией. При структурной ошибке файла база не меняется.
- Период задаётся в диалоге экспорта Telegram Desktop: «с даты» и «по дату». Программа не добавляет собственный фильтр по датам.
- Отчёт о результате содержит только числа: новые, уже имеющиеся и пропущенные записи. Текст публикаций не выводится.
- Документация: как экспортировать канал, импортировать файл и удалить экспорт после импорта.

**Out of scope**

- Прямое подключение к Telegram API, вход в аккаунт и автоматическая синхронизация. Существующие команды `login`, `source add` и `sync` продолжают явно отказывать.
- Группы, обсуждения каналов и комментарии, личные чаты.
- Медиафайлы, HTML-экспорт и полный экспорт аккаунта.
- Отражение последующих изменений и удалений публикаций в Telegram.
- Полнотекстовый поиск, правила отбора, теги и закладки — MVP-03. Веб-интерфейс — MVP-04.
- Автоматический запуск экспорта, управление Telegram Desktop или чтение его локальных данных.
- Использование содержимого для AI или передача внешним сервисам.

## Approach

### Проверенные внешние факты

- В исходном коде Telegram Desktop экспорт одного чата расширяет настройки до полной истории всех типов чатов (`NormalizeSettings` в [export_controller.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/export_controller.cpp)). Поэтому для канала выгружаются все посты, а не только собственные сообщения пользователя. Ограничение «только мои сообщения» относится к общему экспорту аккаунта (`Settings::validate` в [export_settings.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/export_settings.cpp)).
- Структура JSON одного чата ([export_output_json.cpp](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/output/export_output_json.cpp)): объект с `name`, `type`, `id` и массивом `messages`. Каждое сообщение содержит `id`, `type` (`message` или `service`), `date`, `date_unixtime`, при редактировании — `edited`, а также `text` и `text_entities`. `text` бывает строкой или массивом строк и объектов, `text_entities` всегда содержит массив объектов с полем `text`.
- Числовой `id` канала в экспорте — «голый» идентификатор без префикса `-100`. Telethon использует тот же вид, поэтому будущий API-путь сможет ссылаться на тот же источник.
- Использование официального приложения не требует собственного `api_id`, сессии или поддержки рекламы в нашей программе.

### Предлагаемый сценарий

Пользователь в Telegram Desktop экспортирует канал в JSON за нужный период, без медиа, и запускает `python -m telegram_knowledge_base import <путь к result.json>`. Программа проверяет файл, создаёт или обновляет источник и сохраняет новые публикации. Для следующего обновления достаточно экспортировать канал с даты последнего импорта или с небольшим перекрытием: уже сохранённые посты будут пропущены.

Слои: разбор и проверка формата экспорта — отдельный адаптер внешнего формата, без доступа к базе. Сценарий импорта в прикладном слое проверяет тип источника и состояние включения, а затем передаёт данные хранилищу. Хранилище записывает источник и публикации одной транзакцией. Курсоры API и cooldown импорт не использует и не изменяет.

Ограничения ввода: обычный локальный файл не больше 512 МБ, кодировка UTF-8, корректный JSON. Номера сообщений и время должны быть положительными целыми. Файл открывается только для чтения и не копируется. Ошибки сообщают причину без фрагментов содержимого файла.

**Rejected alternatives:**

- Прямое чтение каналов через API без поддержки спонсированных сообщений нарушает п. 3.3 условий Telegram API.
- Чтение каналов через их группы обсуждения, куда автоматически попадают посты, формально обходит то же требование. Отклонено.
- Импорт HTML-экспорта отклонён: формат предназначен для просмотра, а не для надёжного машинного разбора.

## Interface Delta

- Новая команда `import <path>`. Код выхода `0` при успехе, `1` при ошибке ввода или базы. В отчёте выводятся название канала и счётчики.
- Запуск без аргументов, `status` и `source list|enable|disable` не меняются. `login`, `source add` и `sync` по-прежнему явно отказывают.
- Сетевых операций, HTTP-сервера и новых переменных окружения нет.

## Open Questions — решены 2026-11-13

1. Принимать только публичные или и закрытые каналы, на которые подписан пользователь? — **Решение:** оба вида. Экспорт выполняет сам пользователь официальным приложением, поэтому прежняя причина ограничиваться публичными каналами отпала.
2. Что делать с постами без текста, например только с фото? — **Решение:** пропускать и показывать их количество в отчёте.
3. Если пост в новом экспорте отредактирован, заменять ли сохранённый текст? — **Решение:** нет, сохранять первую версию, как решено ранее. Обновление правок — отдельный будущий пункт.
4. Как поступить с одним некорректным сообщением в файле? — **Решение:** отклонить весь файл без изменения базы. Официальный экспорт не должен содержать такие записи, а частичный импорт скрыл бы проблему.
5. Нужен ли собственный фильтр дат в программе? — **Решение:** нет, период задаётся в диалоге экспорта Telegram Desktop.
6. Что делать с готовой заблокированной API-основой? — **Решение:** оставить без изменений. При закрытии добавить в backlog пункт о прямом доступе с поддержкой спонсированных сообщений каналов. Зарегистрированное в Telegram название программы не должно содержать слово «Telegram» (п. 2.3 условий).
