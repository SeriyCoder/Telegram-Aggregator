## Problem

Пользователь не может официально экспортировать защищённый канал, но Telegram
Desktop показывает пункт экспорта у связанной группы обсуждения, куда исходные
посты канала автоматически публикуются рядом с комментариями. Нужен узкий
локальный импорт, который сохраняет только эти исходные посты, не читает
Telegram, не хранит участников и не втягивает комментарии в текущую текстовую
базу.

## History

MVP-02 разрешил импорт только `public_channel` и `private_channel`; произвольные
группы и группы обсуждений тогда были отклонены. Позже реальный официальный
экспорт `Пелливерт. Чат` показал безопасно распознаваемый подвид: исходные
посты канала имеют одновременно непустое поле `saved_from` и
`forwarded_from_id`, начинающийся с `channel`, а пользовательские комментарии
этих полей не имеют. В файле 45,32 МБ: 34 439 записей, из них 33 742 сообщения,
697 служебных записей, 847 исходных постов канала; 748 имеют текст или подпись,
99 содержат только медиа без текста. Реальные тексты и участники не
используются в тестах.

## Scope

**In scope**

- Расширение существующей локальной команды `import <path>` на официальный
  JSON-экспорт связанной группы обсуждения типов `public_supergroup` и
  `private_supergroup`.
- Импорт только исходных постов связанного канала, явно отмеченных обоими
  полями: непустым `saved_from` и `forwarded_from_id` с префиксом `channel`.
  Комментарии и произвольные пересылки других источников пропускаются.
- Использование группы обсуждения как отдельного источника: её числовой `id`
  и `name` из заголовка экспорта, а `telegram_id` исходного канала и имена
  участников не сохраняются.
- Сохранение только сообщений `type = "message"` с непустым текстом или
  подписью. Текст собирается из `text_entities` в исходном порядке, при их
  отсутствии используется строковое поле `text`.
- Время берётся из `date_unixtime` и переводится в UTC в существующем формате.
  Номер `id` сообщения группы используется как стабильный идентификатор поста
  внутри источника для повторного и перекрывающегося импорта.
- Служебные записи, комментарии, остальные пересланные сообщения и исходные
  посты только с медиа без текста увеличивают `Skipped`, но не создают постов.
  Сами медиафайлы не читаются и не копируются.
- Один файл импортируется одной транзакцией: структурная ошибка не изменяет
  базу. Существующая сохранённая версия поста не заменяется.
- Отчёт выводит только название источника и числа `New`, `Existing`, `Skipped`;
  текст постов, имена участников, их ID и содержимое файла не выводятся.
- README и спецификация описывают официальное различие между экспортом канала
  и узким импортом связанной группы обсуждения.

**Out of scope**

- Импорт комментариев, ответов, авторов, реакций, голосов и других данных
  участников; будущий режим «все сообщения» и фильтрация по людям требуют
  отдельного пункта.
- Связь комментария с исходным постом и хранение `reply_to_message_id`.
- Медиафайлы, OCR, транскрибация аудио и видео, каталог изображений; подпись
  к медиа импортируется как текст, само медиа — нет.
- Автотеги, правила отбора, поиск и закладки — MVP-03.
- Произвольные супер-группы без явного маркера `saved_from` на исходных постах
  канала, личные чаты, полный экспорт аккаунта и HTML-экспорт.
- Обход запрета сохранения содержимого, автоматизация Telegram Desktop,
  скрейпинг, Telegram API, вход в аккаунт, сеть и внешние AI-сервисы.
- Дедупликация одного и того же поста между двумя разными источниками импорта
  — прямым экспортом канала и экспортом его группы обсуждения.

## Approach

Существующий адаптер `telegram_export` продолжает полностью разбирать файл до
сохранения. Для заголовков каналов поведение MVP-02 не меняется. Для супер-группы
адаптер должен требовать явный признак связанного канала: хотя бы один
`type = "message"` имеет непустой `saved_from` и `forwarded_from_id` канала.
В предметный результат такой файл попадает с отдельным признаком «исходные
посты канала из обсуждения»; прикладной слой не принимает произвольную группу
только потому, что её `is_channel` равно `False`.

Источник в базе обозначается группой обсуждения: её `id` и `name` из заголовка
экспорта. Это позволяет повторно импортировать тот же файл и перекрывающиеся
периоды с устойчивым ключом «источник группы + ID сообщения в группе». Прямой
экспорт исходного канала имеет другой ID источника и другой набор номеров
сообщений; экспорт группы не содержит надёжного исходного номера поста канала,
поэтому межисточниковая дедупликация не объявляется.

Для каждого сообщения выбор выполняется только по структуре экспорта. Имена,
ID участников, реакции, ответы и иные поля комментариев игнорируются. Пустое
медиа без текста остаётся пропущенным. Ошибки содержат только безопасную причину
без фрагментов текста, имени участника или пути к локальному файлу.

**Rejected alternative:** импортировать всю группу и позднее пытаться отличить
комментарии по тексту или автору — это преждевременно хранит персональные данные
участников и скрывает пограничные ошибки выбора.

**Rejected alternative:** использовать HTTP, Telegram API или чтение внутренних
данных Telegram Desktop для доступа к защищённому каналу — это обход
официальной границы доступа и запрещено правилами проекта.

## Data / Schema Delta

| Entity / field | Change | Version or migration impact |
| --- | --- | --- |
| `sources` | Допускается источник типа публичной или закрытой супер-группы с `username = NULL`; ID и название берутся из заголовка группы | Миграция не нужна: хранятся тот же `telegram_id`, `title` и `enabled`; тип импорта нужен только в памяти |
| `posts` | В качестве `message_id` используется ID сообщения группы; сохраняются только отфильтрованные исходные посты канала | Без изменения схемы; существующий уникальный ключ обеспечивает идемпотентность |
| Данные участника | Имена, `from_id`, реакции и `reply_to_message_id` не сохраняются | Новых полей нет |
| `sync_state`, `api_cooldown` | Импорт их не читает и не меняет | Без изменений |

## Interface Delta

- Существующая команда `import <path>` принимает экспорт связанной группы
  обсуждения и продолжает принимать экспорты MVP-02.
- Произвольная группа без явных исходных постов канала отклоняется с безопасным
  сообщением; личные чаты и полный экспорт аккаунта продолжают отклоняться.
- Строка названия в отчёте становится общей `Source: <name>` вместо
  ориентированной только на каналы `Channel: <name>`. Числа и коды выхода не
  меняются.
- Отключённый источник группы не импортируется. Сеть, сервер и переменные
  окружения не добавляются.

## Privacy and Credential Safety

| Question | Answer |
| --- | --- |
| Is any Telegram credential or session material introduced, moved or exposed? | Нет. Команда читает только файл экспорта, не вызывает Telegram-адаптер и не получает учётные данные. |
| Can an unauthenticated client reach any content-bearing route or file? | Нет. HTTP-сервера и маршрутов по-прежнему нет; база остаётся локальной. |
| Does the change alter where local data or session files are stored? | Нет. База остаётся в проверенном `TKB_DATA_DIR`; `result.json` остаётся файлом пользователя и исключён из Git. |
| Could an error, log, template or response reveal secrets or private content? | Разборщик не должен включать текст, имена/ID участников или фрагменты файла в ошибки и вывод. Реальные личные поля комментариев не попадают в предметные модели. |
| Does the change affect rate-limit handling or remote connectivity? | Нет. Импорт полностью локальный и офлайн, а курсоры и cooldown не меняются. |
| How it is proven by tests | Синтетические супер-группы проверяют выбор только `saved_from`-постов, отказ для обычной группы, пропуск комментариев/служебных/медиа, отсутствие участников в результатах и ошибках, идемпотентность и атомарный отказ. Автофикстура запрещает сеть. |

## Open Questions — решены 2026-11-22

1. Официально экспортировать связанную группу и отбирать автоматически
   размещённые посты канала — разрешить это после прежнего отказа MVP-02? —
   **Решение:** да, узко: только штатный JSON-экспорт Telegram Desktop и
   сообщения с явным сочетанием `saved_from` + `forwarded_from_id`; это не
   обращается к Telegram и не обходит техническую границу доступа.
2. Какой объект считать источником: исходный канал или группу обсуждения? —
   **Решение:** группу обсуждения (`id` и `name` из заголовка). Это
   устойчиво для повторного импорта и не придумывает отсутствующий ID исходного
   сообщения канала.
3. Что означает «без дублей»? — **Решение:** только внутри одного
   источника группы. Прямой экспорт канала и
   экспорт связанной группы остаются
   разными источниками; безопасно дедуплицировать их между собой нельзя,
   потому что исходный номер поста канала в файле группы отсутствует.
4. Как поступить с супер-группой без отмеченных постов `saved_from`? —
   **Решение:** отклонить весь файл как непроверенную произвольную группу,
   а не импортировать пустую выборку или комментарии.
5. Как учитывать пост только с медиа? — **Решение:** если есть текстовая
   подпись — сохранить её; иначе пропустить и
   увеличить `Skipped`; медиа-файлы,
   OCR и видео остаются будущим отдельным объёмом.
6. Когда появится фильтр по участникам и сохранение имён? — **Решение:**
   отдельный будущий пункт после MVP-05. Это потребует отдельного решения о
   хранении персональных данных, модели комментария и связи с постом.
7. Менять ли текущую строку отчёта `Channel:` на `Source:`? —
   **Решение:** да, потому что команда теперь принимает не только
   каналы, а содержимое и коды выхода остаются совместимыми.
