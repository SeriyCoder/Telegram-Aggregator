# Telegram Knowledge Base

Локальная персональная база знаний для публикаций из выбранных Telegram-каналов.
Приложение создаёт локальную базу, поддерживает работу с уже добавленными
локально источниками и импортирует публикации каналов из официального
JSON-экспорта Telegram Desktop. Реальный вход и доступ к Telegram намеренно
заблокированы до выяснения применимости требований платформы к этому сценарию.
HTTP-сервер ещё не реализован.

## Требования

- Python 3.12 или новее
- Windows PowerShell 5.1 или новее

## Установка

Из корневого каталога проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Файл `.env.example` перечисляет стандартные ограничения. Приложение читает
настройки из окружения процесса и не загружает `.env` автоматически.

| Переменная | По умолчанию | Допустимое значение |
| --- | --- | --- |
| `TKB_DATA_DIR` | Системный каталог пользовательских данных | Не пустой абсолютный путь вне каталога проекта |
| `TKB_COLLECTION_LIMIT` | `500` | Целое число от 1 до 500 |
| `TKB_PAGE_SIZE` | `50` | Целое число от 1 до 100 |

Данные и защищённая сессия Telegram должны храниться вне каталога проекта.
`TKB_DATA_DIR` обязан быть локальным каталогом, не сетевой папкой и не папкой
OneDrive, Dropbox или Google Drive. SQLite не шифрует сохранённые публикации.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base
```

При первом запуске создаётся SQLite-база с начальной схемой в пользовательском
каталоге данных. Повторный запуск сохраняет существующие данные.

Доступны локальные команды:

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base status
.\.venv\Scripts\python.exe -m telegram_knowledge_base source list
.\.venv\Scripts\python.exe -m telegram_knowledge_base source enable <ID>
.\.venv\Scripts\python.exe -m telegram_knowledge_base source disable <ID>
```

Команды `login`, `source add` и `sync` завершаются безопасным сообщением, пока
не снята блокировка реального доступа. Даже заданные `TKB_API_ID` и
`TKB_API_HASH` не включают подключение. Собранная версия поста впоследствии
автоматически не обновляется и не удаляется.

## Импорт публикаций из экспорта Telegram Desktop

Публикации каналов добавляются без входа программы в Telegram — через
официальный экспорт Telegram Desktop:

1. Откройте канал в официальном приложении Telegram Desktop.
2. Меню **⋮ → «Экспорт истории чата»**. Снимите отметки со всех медиа,
   выберите формат **JSON** и задайте период «с даты» и «по дату».
3. Сохраните экспорт в локальную папку вне OneDrive и вне каталога проекта.
4. Импортируйте полученный `result.json`:

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base import <путь к result.json>
```

Отчёт содержит название канала и счётчики: `New` — сохранённые новые
публикации, `Existing` — уже имевшиеся, `Skipped` — пропущенные служебные
записи и посты без текста. Текст публикаций на экран не выводится.

Поддерживаются только экспорты одного канала — публичного или закрытого.
Группы, личные чаты и полный экспорт аккаунта отклоняются. Повторный или
перекрывающийся импорт не создаёт дублей и не заменяет уже сохранённые
версии постов, поэтому для обновления достаточно экспортировать канал с даты
последнего импорта или с небольшим перекрытием.

После успешного импорта удалите папку экспорта: её содержимое уже в базе, а
лишняя копия публикаций на диске не нужна. Файлы `result.json` и папки
`ChatExport_*` исключены из репозитория через `.gitignore`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m mypy src
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

Все тесты работают офлайн и не требуют Telegram-сессии.
