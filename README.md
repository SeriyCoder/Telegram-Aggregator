# Telegram Knowledge Base

Локальная персональная база знаний для публикаций из выбранных Telegram-каналов.
Приложение создаёт локальную базу, поддерживает работу с уже добавленными
локально источниками и импортирует публикации каналов из официального
JSON-экспорта Telegram Desktop. Реальный вход и доступ к Telegram намеренно
заблокированы до выяснения применимости требований платформы к этому сценарию.
HTTP-сервер ещё не реализован.

## Требования

- Python 3.12 или новее
- Windows PowerShell 5.1 или новее

## Установка

Из корневого каталога проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Файл `.env.example` перечисляет стандартные ограничения. Приложение читает
настройки из окружения процесса и не загружает `.env` автоматически.

| Переменная | По умолчанию | Допустимое значение |
| --- | --- | --- |
| `TKB_DATA_DIR` | Системный каталог пользовательских данных | Не пустой абсолютный путь вне каталога проекта |
| `TKB_COLLECTION_LIMIT` | `500` | Целое число от 1 до 500 |
| `TKB_PAGE_SIZE` | `50` | Целое число от 1 до 100 |

Данные и защищённая сессия Telegram должны храниться вне каталога проекта.
`TKB_DATA_DIR` обязан быть локальным каталогом, не сетевой папкой и не папкой
OneDrive, Dropbox или Google Drive. SQLite не шифрует сохранённые публикации.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base
```

При первом запуске создаётся SQLite-база с начальной схемой в пользовательском
каталоге данных. Повторный запуск сохраняет существующие данные.

Доступны локальные команды:

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base status
.\.venv\Scripts\python.exe -m telegram_knowledge_base source list
.\.venv\Scripts\python.exe -m telegram_knowledge_base source enable <ID>
.\.venv\Scripts\python.exe -m telegram_knowledge_base source disable <ID>
```

Команды `login`, `source add` и `sync` завершаются безопасным сообщением, пока
не снята блокировка реального доступа. Даже заданные `TKB_API_ID` и
`TKB_API_HASH` не включают подключение. Собранная версия поста впоследствии
автоматически не обновляется и не удаляется.

## Импорт публикаций из экспорта Telegram Desktop

Публикации каналов добавляются без входа программы в Telegram — через
официальный экспорт Telegram Desktop. Поддерживаются два безопасных пути:

1. Для обычного публичного или закрытого канала: откройте канал и выберите
   **⋮ → «Экспорт истории чата»**.
2. Если сам канал запрещает сохранение, но у него доступна связанная группа
   обсуждения: откройте именно её и экспортируйте её историю. Импортёр сохранит
   только автоматически размещённые исходные посты канала и пропустит
   комментарии участников.
3. В обоих случаях снимите отметки со всех медиа, выберите формат **JSON** и
   задайте период «с даты» и «по дату». Само медиа не копируется.
4. Импортируйте полученный `result.json`:

```powershell
.\.venv\Scripts\python.exe -m telegram_knowledge_base import <путь к result.json>
```

Отчёт содержит название источника и счётчики: `New` — сохранённые новые
публикации, `Existing` — уже имевшиеся, `Skipped` — пропущенные записи.
В экспорте группы это комментарии, прочие пересылки, служебные записи и посты
без текста. Имена и ID участников не сохраняются и не выводятся. Текст
публикаций на экран не выводится.

Поддерживаются экспорт одного канала — публичного или закрытого — либо
связанная публичная или закрытая супер-группа с явно отмеченными исходными
постами канала. Произвольные группы, личные чаты и полный экспорт аккаунта
отклоняются. Подпись к медиа сохраняется как текст; медиа без подписи пропускается.
Повторный или перекрывающийся импорт того же источника не создаёт дублей и не
заменяет сохранённые версии.

После успешного импорта удалите папку экспорта: её содержимое уже в базе, а
лишняя копия публикаций на диске не нужна. Файлы `result.json` и папки
`ChatExport_*` исключены из репозитория через `.gitignore`.

## Локальные фильтры, теги и поиск

База поддерживает пользовательские теги, буквальные правила автотегирования,
глобальные правила `include`/`exclude`, закладки и полнотекстовый поиск SQLite
FTS5. Теги создаются пользователем с нуля; автоматическое назначение вычисляется
из локальных правил без AI и без передачи содержания наружу. Несколько правил
включения и выбранных тегов объединяются по OR, исключения применяются после.

Поиск работает локально по текстам и поддерживает кириллицу, безопасно трактует
специальные символы и не интерпретирует пользовательский ввод как SQL, regex или
язык операторов FTS. При обновлении схемы все уже импортированные посты попадают
в индекс одной транзакцией.

Пользовательский просмотр постов, поиск в браузере, создание и редактирование
тегов через GUI реализуются в MVP-04. Текущая CLI-команда продолжает показывать
только агрегированные счётчики и не выводит текст публикаций.
